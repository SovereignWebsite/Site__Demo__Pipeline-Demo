Asking for a site

A site starts as one file. This is the request that made this site:

{
  "label": "pipeline-demo",
  "title": "A site from one request",
  "description": "Made by the Sovereign Website pipeline from one request folder.",
  "kind": "demo"
}

The fields

FieldRule
labelLower-case letters, digits and hyphens, at most 40 characters, matching the folder name. It becomes the address <label>.sovereignwebsite.site and the repository Site__<label>. Reserved: www, hub, vault, api, admin, mail, factory.
titleAt most 80 characters. The first page's heading.
descriptionAt most 200 characters. The first page's summary.
kinddemo for an example made by the team, owner for a site that belongs to someone.
groupRequired. The area the site belongs to, from the list below. The address becomes <label>.<group>.sovereignweb.site.
accessOptional. vault for a private site: the public address shows only a holding page, and the site itself is in an encrypted vault opened with its QR code.

Groups

New sites are made on sovereignweb.site, in one of these groups (Dinis Cruz, 20 November 2026: "everything should have a group"; more will be added as we go; the Factory's requests/README.md is the list in force):

GroupForExample
artistcreative portfolios<name>.artist.sovereignweb.site
cvcareer profiles<name>.cv.sovereignweb.site
companycompanies<name>.company.sovereignweb.site
organisationgroups that are not companies<name>.organisation.sovereignweb.site
investinvestment firms<name>.invest.sovereignweb.site
designerdesign portfolios<name>.designer.sovereignweb.site
toolsmall useful tools<name>.tool.sovereignweb.site
founderfounders and their ventures<name>.founder.sovereignweb.site
startupsbrochure sites for startups, pointing to their own sites<name>.startups.sovereignweb.site
demodemonstrations of the pipeline and of what a site can do<name>.demo.sovereignweb.site
agentsthe Sovereign Website agents' own sites<name>.agents.sovereignweb.site

No em or en dashes anywhere in a request. The rules are checked by build/requests.mjs and the tests before anything is made.

People and privacy

A request names no private person. The Factory is a public repository, so an owner's details stay out of it until they agree. A site about a person is built only with that person's consent.

How a request is made today

  1. Dinis asks for a site, in a session with the team.
  2. The sites agent drafts the label, title, description and kind, and Dinis says yes to that site.
  3. The request goes to the Factory's agent, which commits it, signed, to dev.
  4. The pipeline does the rest, as on How it works.
  5. For a private site, the site's own agent seals the vault and gives the QR code only to the person asking; no other agent or site sees it.
